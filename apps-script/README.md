# 상담 저장 후 대표자 문자 알림

기존 `예약` 시트의 14개 열과 홈페이지 제출 방식은 유지한다. 저장과 `SpreadsheetApp.flush()` 완료 뒤 SOLAPI로 대표자에게 SMS 한 건을 요청한다. 문자에는 접수 사실과 한국 시간만 포함하며 고객 이름·연락처·문의 내용은 포함하지 않는다.

스크립트 속성(웹 소스에 넣지 않음):

- `OWNER_SMS_ENABLED`: `true`일 때 발송
- `SOLAPI_API_KEY`, `SOLAPI_API_SECRET`: 기존 SOLAPI 계정 인증 정보
- `SOLAPI_SENDER`: SOLAPI에 승인된 발신번호

수신번호는 `Code.gs`의 `OWNER_SMS_TO`로 고정한다. 홈페이지 입력값으로 바꿀 수 없다. 상담 저장 후 별도 숨김 시트 `문자알림 로그`에 예약 행과 발송 접수 결과를 남긴다. 오류·타임아웃은 상담 저장을 취소하지 않으며, 응답 유실에 따른 중복 문자 방지를 위해 자동 재발송하지 않는다. `발송 접수`는 업체의 접수이며 단말 수신 완료와는 구분된다.

`testOwnerSms()`는 상담 행을 만들지 않고 연결 테스트 문자 한 건을 요청한다. 실제 SOLAPI 이용 요금은 기존 계정에 적용된다.

코드 수정 후에는 기존 웹 앱 배포를 새 버전으로 업데이트해야 홈페이지에 적용된다. 배포 ID와 기존 URL은 유지한다. 외부 서비스 연결을 위한 Google 권한 승인이 추가로 필요할 수 있다.

검증: 저장 선행, 14개 열 유지, 문자 실패에도 접수 유지, 스팸·미동의 제출 미발송, 대표자 번호 고정, 고객 정보 미포함, HMAC 인증, 90바이트 이내 SMS, 결과 미확인 시 미재발송을 `node tests/booking-sms.test.cjs`로 확인한다.

2026-10-06 연결 상태: 기존 SOLAPI 인증 정보는 Apps Script 속성에 설정 완료. 로컬 회귀 테스트 통과. 사용자 승인 후 표준 Google Cloud 프로젝트 `diloop-booking-sms`(번호 `1012204663432`)로 연결했고, OAuth 범위는 `spreadsheets.currentonly`와 `script.external_request` 두 개만 등록했다. 운영자 계정의 권한 승인 완료. `testOwnerSms()`의 실제 SMS 한 건은 SOLAPI 상태 `4000`(발송 완료)으로 확인했다. 기존 홈페이지 접수 URL은 그대로 유지하며 버전 4로 배포 완료.

처음 실제 홈페이지 접수 회귀 테스트에서는 저장 공간 초과(15GB 중 78.57GB 사용)로 예약 행 저장이 실패했다. 사용자가 용량을 추가한 뒤 Google One에서 400GB 중 78.57GB 사용을 확인했고, 홈페이지 폼으로 다시 제출한 명확한 테스트 상담은 예약 5행에 기존 14개 열 그대로 저장됐다. 숨김 `문자알림 로그`에는 예약 5행과 발송 접수 결과가 기록됐으며 같은 그룹 ID의 SOLAPI 상태 `4000`(발송 완료)을 확인했다. 테스트 상담은 실제 고객이 아님을 이름·상호·문의에 명시했다. 원래 고객 행은 수정하지 않았다. 기존 프런트는 `no-cors` 제출이므로 화면의 접수 표시만으로 저장 성공을 판단하면 안 된다.

사용자가 Google 운영 모드 전환 확인을 눌렀고, OAuth 게시 상태 `프로덕션 단계`를 확인했다. 기존 홈페이지·개인정보처리방침 URL과 `diloop.kr` 도메인을 브랜딩 정보에 등록했다. Google 앱 검증은 완료된 상태가 아니며, 운영자 본인 1명 사용 기준으로 구성돼 있다(검증 전 사용자 한도 100명).

운영 모드에서 기존 두 권한의 새 동의를 사용자 본인이 완료했다. Google 승인 성공 화면과 `showOwnerSmsApproval()` 실행 결과 `NOT_REQUIRED`를 확인했다. 추가 문자는 발송하지 않았다. 상담 저장 → 자동 SMS → 숨김 발송 로그 및 운영 모드 승인 갱신까지 검증 완료. 기본 14개 열, 가격, 홈페이지 제출 방식은 유지한다.
